# APAC Skills 资产管理设计文档

## 概述

本文档描述了APAC团队skill资产项目的组织和管理设计方案。项目目标是建立一个统一的skill资产库，支持团队内部知识共享、跨团队复用和skill版本管理。

## 项目背景

- **团队规模**：10-30人
- **skill数量**：20-50个
- **当前状态**：skill分散在各个项目中
- **主要目标**：团队内部知识共享、跨团队复用、skill版本管理

## 设计方案：Monorepo with 分类结构

### 目录结构

```
apac-skills/
├── README.md                    # 项目介绍和快速开始
├── CONTRIBUTING.md              # 贡献指南
├── LICENSE
├── .github/                     # CI/CD配置
├── templates/                   # skill模板和规范
│   ├── skill-template/
│   ├── wiki-template/
│   └── tool-template/
├── ai-agent-skills/             # AI agent相关技能
├── ai-coding-skills/            # AI编码实践
├── ai-tools/                    # AI工具使用指南
├── ai-wiki/                     # 业务知识库
└── docs/                        # 项目文档
```

### Skill元数据规范

每个skill必须包含`skill.json`元数据文件：

```json
{
  "name": "skill名称",
  "version": "1.0",
  "description": "简短描述",
  "category": "ai-agent|ai-coding|ai-tools|ai-wiki",
  "tags": ["标签1", "标签2"],
  "author": "作者",
  "team": "所属团队",
  "dependencies": ["依赖的其他skill"],
  "platform": ["支持的平台"],
  "lastUpdated": "2024-01-01",
  "rating": 4.5,
  "usageCount": 100
}
```

### 版本管理策略

#### 版本号规范
- 简单递增版本号（1.0, 1.1, 2.0）
- 主要功能更新：主版本号+1（1.0 → 2.0）
- 小更新和修复：次版本号+1（1.0 → 1.1）

#### 更新流程
- 直接在main分支开发（小更改）
- 重大更改创建分支 → PR → 审查
- 简化CI检查（格式、基本测试）

#### 依赖管理
- 声明依赖但不强制版本锁定
- 手动管理依赖关系
- README中说明兼容性

### 文档和搜索机制

#### 文档标准
- 每个skill必须有README.md（说明、用法、示例）
- 可选WIKI.md（详细文档）
- 代码示例和最佳实践

#### 搜索机制
- 基于标签和类别的搜索
- 全文搜索（描述、文档）
- 按评分和使用量排序

#### 发现方式
- 主页README有分类目录
- 按团队、平台、用途分组
- 定期更新精选skill列表

### 跨团队复用机制

#### 访问控制
- 默认公开读取权限
- 写入权限按团队分配
- 敏感skill可设为内部可见

#### 复用方式
- 直接引用（Git submodule）
- 复制到本地项目
- 通过包管理器安装（如果支持）

#### 跨团队协作
- 贡献指南（CONTRIBUTING.md）
- 代码审查流程
- 跨团队沟通渠道（如Slack频道）

#### 迁移路径
- 盘点现有分散在各项目中的skill，列出清单
- 按使用频率和重要性排序，优先迁移高频skill
- 每个skill迁移时补充元数据和README
- 原项目保留引用链接，避免破坏现有使用

## 实施计划

### 阶段1：基础结构搭建
1. 创建目录结构
2. 编写README.md和CONTRIBUTING.md
3. 创建skill模板
4. 设置CI/CD基础配置

### 阶段2：现有skill迁移
1. 评估现有分散的skill
2. 制定迁移优先级
3. 逐步迁移skill到新结构
4. 更新元数据和文档

### 阶段3：工具和流程完善
1. 实现搜索和发现功能
2. 建立评分和反馈机制
3. 完善跨团队协作流程
4. 培训团队成员

## 成功标准

1. **知识共享**：团队成员能快速找到所需skill
2. **跨团队复用**：其他团队能轻松使用skill
3. **版本管理**：skill有清晰的版本历史和更新记录
4. **文档质量**：每个skill都有完整的文档和示例
5. **团队采用**：80%以上的团队成员使用统一平台

## 风险和缓解

1. **风险**：团队成员不适应新结构
   - 缓解：提供培训和支持，渐进式迁移

2. **风险**：skill质量参差不齐
   - 缓解：建立质量标准和审查流程

3. **风险**：维护成本增加
   - 缓解：自动化工具和清晰的贡献指南
