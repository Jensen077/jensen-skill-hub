# 交付前自检清单

## 结构

- [ ] 平台专题在项目落地之前
- [ ] 平台能力与项目扩展严格分离
- [ ] 每个平台能力都能回答「换项目是否成立」
- [ ] 项目章节只写扩展，不重复平台原理
- [ ] 有复用判断表，不只罗列项目
- [ ] 有接入 checklist
- [ ] 文首有阅读建议和 frontmatter（知识库场景）

## 证据

- [ ] 接口路径、字段、默认值来自源码
- [ ] 错误码、异常分支来自源码
- [ ] 响应示例来自真实日志或代码结构
- [ ] 耗时来自日志，不是估算
- [ ] 日志条数没有被写成请求数
- [ ] 代码与旧文档冲突处已标注并以代码为准
- [ ] 无法确认的内容标「待确认」

## 可执行性

- [ ] curl 可直接复制执行
- [ ] 加密/签名占位符说明清楚
- [ ] 环境域名、context-path 正确
- [ ] 请求头、鉴权方式完整
- [ ] 响应字段名与代码一致（如 url / redirectUrl / orderDetailUrl）

## 安全

- [ ] 客编、订单号、token、短链已脱敏
- [ ] 密钥、证书、内部地址未写入文档
- [ ] 生产日志样例不包含可定位个人的信息

## 反模式

- 把某个项目的特殊逻辑写成平台能力
- 只贴源码路径，不解释调用关系
- 只写「支持 XX」，不写参数和限制
- 用「默认」「一般」代替实际配置值
- 把配置扩展写成开发改造
- 编造未验证的字段、错误码、耗时
- 文档只面向单项目，无法复用到同能力的新项目
